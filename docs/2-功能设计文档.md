# 功能设计文档

## 1. 系统架构设计

### 1.1 整体架构

系统采用四层分层架构：

```
┌─────────────────────────────────────────────┐
│           B/S 前端 (对话 + 审计面板)          │
├─────────────────────────────────────────────┤
│        Agent 核心层 (调度 + 思维链管理)        │
├──────────┬──────────────┬───────────────────┤
│ 意图解析层 │  安全护栏层   │   执行引擎层       │
│ (NLU)    │ (过滤/校验)   │ (MCP Tools/插件)  │
├──────────┴──────────────┴───────────────────┤
│           OS 底层 (Linux / LoongArch)         │
└─────────────────────────────────────────────┘
```

### 1.2 模块划分

| 模块 | 职责 | 主要文件 |
|------|------|----------|
| 前端模块 | 用户界面展示和交互 | templates/, static/ |
| API模块 | HTTP接口定义 | api/ |
| Agent模块 | 核心调度逻辑 | core/agent.py |
| MCP模块 | 工具协议实现 | mcp/ |

| 数据模块 | 数据模型定义 | models/ |

## 2. 核心模块设计

### 2.1 Agent调度器

**职责**：协调LLM、MCP工具、安全护栏的工作

**核心流程**：
1. 接收用户输入
2. 执行输入安全检查
3. 构建LLM请求
4. 调用LLM获取响应
5. 处理工具调用（如有）
6. 执行输出安全校验
7. 执行工具
8. 生成最终响应

**关键类**：
- `Agent`: Agent调度器主类
- `LLMClient`: 大模型调用客户端
- `ChainOfThoughtManager`: 思维链管理器
- `RootCauseAnalyzer`: 智能根因分析器

### 2.2 智能根因分析模块

**职责**：异常检测 → 关联分析 → 根因推断 → 修复建议

**分析流程**：
1. **数据采集**：调用MCP工具获取CPU、内存、磁盘、进程、日志、网络数据
2. **异常检测**：基于阈值规则检测六维度异常
   - CPU使用率 > 85% (警告) / > 95% (严重)
   - 内存使用率 > 80% (警告) / > 95% (严重)
   - 磁盘使用率 > 85% (警告) / > 95% (严重)
   - 僵尸进程 > 5个
   - 错误日志 > 10条/分钟
   - OOM事件检测
3. **关联分析**：将异常关联到具体原因
   - CPU高 → 找出高CPU进程 → 判断是否异常
   - 内存高 → 检查OOM日志 → 定位内存泄漏进程
   - 磁盘满 → 分析大目录 → 建议清理
4. **根因推断**：基于规则引擎推断根本原因
5. **健康评分**：0-100分系统健康度评估
6. **修复建议**：针对性的操作建议

### 2.3 MCP协议实现

**职责**：标准化工具调用协议

**核心设计**：
- `MCPProtocol`: 协议核心，管理工具注册和执行
- `ToolDefinition`: 工具定义，包含名称、描述、参数、风险等级等
- `ToolExecutor`: 工具执行器基类
- `ToolRegistry`: 工具注册中心

**工具分类（24个）**：
- 系统感知类（低风险）：get_system_info, get_cpu_usage, get_memory_usage, get_disk_usage
- 原生命令类（低风险）：lsof_ports(端口占用), dmesg_kernel_log(内核日志), iostat_disk_io(磁盘IO)
- 网络感知类（低风险）：get_network_status, get_network_connections, netstat_connections, ping_host
- 进程管理类（低/高风险）：get_process_list, get_process_detail, detect_zombies, kill_process
- 服务管理类（低/中风险）：list_services, get_service_status, restart_service, stop_service, get_system_logs
- 文件操作类（低/高风险）：delete_file, chmod, config_drift_check
- 智能诊断类（低风险）：diagnose_system

### 2.4 安全护栏

**职责**：三层安全防护机制（11条安全规则 + LLM输出校验）

**第一层：输入过滤**
- Prompt注入检测（中英文模式匹配，38种注入模式）
- 危险命令检测（rm -rf, shutdown, mkfs等，7种模式）
- 敏感信息泄露检测（密码、API Key等，4种模式）

**第二层：输出校验（11条规则 + LLM输出内容校验）**
1. 禁止删除系统关键路径
2. 禁止kill PID 1（init进程）
3. 禁止设置777权限
4. 限制关键系统服务停止（sshd, systemd等）
5. 禁止操作/dev设备文件
6. 路径遍历检查
7. 禁止递归删除关键目录（rm -rf等效）
8. 拦截不安全权限设置（666, 敏感文件可写等）
9. 防止批量终止进程（kill PID 0等）
10. 禁止篡改配置基线文件（保护配置漂移检测能力）
11. 禁止停止安全监控服务（auditd/rsyslog/firewalld等）

**LLM输出内容校验**：检测LLM回复中的危险shell命令（10种高危模式：rm -rf、mkfs、dd、chmod 777、/etc/passwd写入、shutdown、kill -9 1、iptables -F等）

**第三层：执行沙箱**
- 路径限制（禁止访问/dev, /proc, /sys）
- 命令白名单
- 资源限制

    "message": "帮我查看系统状态",
