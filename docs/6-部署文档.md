# 部署文档

## 1. 部署概述

### 1.1 部署方式

本项目支持以下部署方式：
- 本地开发环境部署
- Docker容器化部署
- 通用 Linux（含 LoongArch 等国产架构）部署

### 1.2 环境要求

| 组件 | 要求 |
|------|------|
| 操作系统 | Linux (含 LoongArch 等国产架构) / Windows / macOS |
| Python | 3.10+ |
| Conda | Miniconda 或 Anaconda |
| Docker | 20.10+ (可选) |
| 内存 | >= 2GB |
| 磁盘 | >= 1GB |

## 2. 本地开发环境部署

### 2.1 安装Conda

```bash
# 下载Miniconda
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh

# 安装
bash Miniconda3-latest-Linux-x86_64.sh

# 配置龙芯Python仓库（仅LoongArch平台需要）
wget https://cloud.loongnix.cn/releases/loongarch64/python/set-pip.sh
chmod +x set-pip.sh
./set-pip.sh
```

### 2.2 创建环境

```bash
# 克隆项目
git clone <repository-url>
cd opschat

# 创建Conda环境
conda env create -f environment.yml

# 激活环境
conda activate opschat
```

### 2.3 配置环境变量

```bash
# 复制示例配置
cp .env.example .env

# 编辑配置
vim .env
```

配置内容：
```env
# LLM配置
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash

# 数据库配置
DATABASE_URL=sqlite:///./data/audit.db

# 安全配置
ENABLE_SECURITY_GUARDRAIL=true
ENABLE_INPUT_SANITIZER=true
ENABLE_OUTPUT_VALIDATOR=true
ENABLE_SANDBOX=true
ENABLE_PERMISSION_SERVICE=true
LOG_LEVEL=INFO

# 服务器配置（默认仅本机监听；内网/公网部署改为 0.0.0.0 并开启认证）
HOST=127.0.0.1
PORT=8000
RELOAD=false

# CORS（默认仅同源本机；* 与 allow_credentials=True 不兼容）
CORS_ORIGINS=http://localhost:8000,http://127.0.0.1:8000

# 基础登录认证（可选，默认关闭）
AUTH_ENABLED=false
AUTH_USERNAME=admin
AUTH_PASSWORD=

# 密钥加密（模型 API 密钥落库加密；留空自动生成 data/.secret_key）
SECRET_KEY=
```

### 2.4 启动服务

```bash
python run.py
```

访问 http://localhost:8000

## 3. Docker部署

### 3.1 构建镜像

```bash
docker build -t opschat .
```

### 3.2 运行容器

```bash
docker run -d \
  --name opschat \
  -p 8000:8000 \
  --env-file .env \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/logs:/app/logs \
  opschat
```

### 3.3 使用Docker Compose

```bash
# 启动服务
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```

### 3.4 龙芯Docker配置

```json
{
  "registry-mirrors": ["https://cr.loongnix.cn"]
}
```

## 5. 反向代理配置

### 5.1 Nginx配置

```nginx
server {
    listen 80;
    server_name opschat.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # SSE支持
        proxy_set_header Connection '';
        proxy_http_version 1.1;
        chunked_transfer_encoding off;
        proxy_buffering off;
        proxy_cache off;
    }
}
```

### 5.2 启用HTTPS

```bash
# 安装certbot
sudo yum install -y certbot python3-certbot-nginx

# 获取证书
sudo certbot --nginx -d opschat.example.com
```

## 6. 系统服务配置

### 6.1 创建systemd服务

```bash
sudo tee /etc/systemd/system/opschat.service <<EOF
[Unit]
Description=OpsChat Service
After=network.target

[Service]
Type=simple
User=opschat
WorkingDirectory=/opt/opschat
Environment=PATH=/opt/opschat/venv/bin
ExecStart=/opt/opschat/venv/bin/python run.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

### 6.2 启用服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable opschat
sudo systemctl start opschat
```

## 6.3 sudo 提权部署注意（权限引擎）

OpsChat 的高危操作审批支持 sudo 提权（`PermissionService.verify_sudo`）。sudo timestamp 默认按 tty 隔离，agent 无 tty 时退化为按父进程（PPID）隔离，因此：

- **单进程部署（默认，`python run.py`）**：confirm 阶段 `sudo -S -v` 刷新 timestamp 后，工具执行阶段的 `sudo` 命令在同一进程（同一 PPID）内免密，密码即焚，无需额外配置。
- **多 worker 部署（uvicorn `--workers N` 等）**：不同 worker 的 PPID 不同，timestamp 不共享，confirm 后其他 worker 执行工具仍需密码。两种解决办法：
  1. 在 sudoers 中配置全局 timestamp：`Defaults timestamp_type=global`（所有进程共享 timestamp，安全边界略降）；
  2. 或保持单进程部署（推荐）。
- 部署用户必须在 sudoers 中（`sudo -v` 能通过）；否则高危操作审批会降级为纯应用确认，不做弱化。

## 6.4 安全部署建议

1. **监听地址**：默认 `HOST=127.0.0.1`（仅本机访问）。如需内网/公网访问，务必：
   - 将 `HOST` 改为 `0.0.0.0`；
   - 开启基础认证：`AUTH_ENABLED=true` + `AUTH_USERNAME`/`AUTH_PASSWORD`（建议强密码，并前置 HTTPS/TLS，Basic Auth 为明文传输）。
2. **模型密钥加密**：模型档案中的 API 密钥以 Fernet 加密落库。单实例部署无需配置，系统自动生成 `data/.secret_key`；**多实例/迁移部署必须显式设置相同的 `SECRET_KEY`**，否则其他实例无法解密密钥。请勿将 `data/.secret_key` 提交到版本库或泄露。
3. **自定义工具限制**：
   - `python` 类型自定义工具已被安全策略禁用（exec 无法沙箱化，可能被用于任意代码执行）；
   - `shell` 类型模板会在创建/更新时检查危险命令（`rm -rf`、`mkfs`、`dd of=/dev/*`、`curl|sh` 等）并拒绝；
   - 风险等级 `high/critical` 的自定义工具即使 `requires_approval=false` 也会强制进入人工审批。
4. **备份安全**：`data/` 目录（数据库 + `.secret_key`）与 `.env`（含可能的明文密钥）应纳入备份，且设置仅属主可读的权限。

## 7. 故障排查

### 7.1 查看日志

```bash
# 应用日志
tail -f logs/opschat.log

# Docker日志
docker logs -f opschat

# systemd日志
journalctl -u opschat -f
```

### 7.2 常见问题

**问题**：端口被占用
```bash
# 查找占用端口的进程
lsof -i :8000

# 杀死进程
kill -9 <PID>
```

**问题**：权限不足
```bash
# 修改文件权限
chmod -R 755 /opt/opschat
chown -R opschat:opschat /opt/opschat
```

**问题**：数据库锁定
```bash
# 删除锁定文件
rm -f data/audit.db-journal
```
